# Linko Core Implementation Plan (Plan 2 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `linko-core` — the C++17 core shared by the server and both apps: protocol v1 envelopes, the call state machine, file chunking, message sync helpers, and the design-token source of truth with its generator.

**Architecture:** One CMake library `linko_core` (pure C++17, no platform code) with GoogleTest suites beside it; every unit is a pure value type or pure function so the same code drives the Windows server and the Apple apps. Design tokens are data (`design-tokens/tokens.json`) plus a stdlib-Python generator whose output (`Tokens.swift`) is committed and freshness-checked. The repo already carries the shared tooling from Plan 1; this plan adds the stack section to its `CLAUDE.md` and repo CI.

**Tech Stack:** C++17, CMake ≥ 3.28 with presets, GoogleTest and nlohmann/json via FetchContent (exact tags, ADR-0002), clang-format/clang-tidy, llvm-cov, Python 3 stdlib.

**Spec:** `linko-apple/docs/superpowers/specs/2026-10-25-linko-design.md` (§4.2 LinkoCore, §4.8 design system, §7 quality gates).

**Plan series:** 1 Foundation (done) → **2 linko-core (this)** → 3 linko-server, 4 linko-apple (in parallel after this).

**Tickets:** this plan document is LNK-5; Tasks 1–8 are LNK-6…LNK-13.

## Global Constraints

- C++17, no platform dependencies in `linko-core`; CI builds on macOS and Windows, Linux preset is an unofficial local dev build only (spec §3, §4.2).
- Warnings are errors: `-Wall -Wextra -Wpedantic -Werror`, MSVC `/W4 /WX` (spec §7).
- TDD: the failing test is written and watched first; no production code without it (CLAUDE.md).
- Coverage gate: ≥ 90 % lines of `linko_core` (spec §7).
- No new dependency without an ADR; versions pinned exactly (CLAUDE.md). New here: GoogleTest and nlohmann/json → ADR-0002 in `linko-apple/docs/adr/`.
- Envelope limits: envelope ≤ 64 KiB, SDP ≤ 32 KiB, strict UTF-8, nesting limit; unknown fields ignored, unknown `type` rejected; `v` mismatch → reply `session.error{code:"unsupported_version"}` (spec §4.2).
- Branches `feature/LNK-<n>-<slug>` → PR to `develop`; Conventional Commits; never commit to `main`/`develop`; never log SDP, ICE credentials, tokens or message bodies (CLAUDE.md).
- Repository text in English (CLAUDE.md).

## Review Focus

1. Hostile JSON — oversized envelope (> 64 KiB), oversized SDP (> 32 KiB), deep nesting, invalid UTF-8, non-object root, wrong field types — must produce path-carrying validation errors, never a crash or a hang. *(Task 2: `test_rejects_oversized_envelope`, `test_rejects_oversized_sdp`, `test_rejects_deep_nesting`, `test_rejects_invalid_utf8`, `test_rejects_non_object_root`)*
2. Duplicate, late or reordered signaling — a second `call.accept`, an answer after hangup, a timer firing after `ended` — the machine stays consistent and emits no effects after `ended`. *(Task 4: `test_ignores_duplicate_accept`, `test_ignores_late_answer_after_ended`, `test_no_effects_after_ended`)*
3. Glare — both sides invite at once; exactly one call survives, deterministically: the lexicographically smaller `callId` wins. *(Task 4: `test_glare_smaller_call_id_survives`, `test_glare_larger_call_id_yields`)*
4. Corrupt, duplicated or gapped file chunks — bit-flip, resend after ack, missing index — reassembly never returns wrong bytes, integrity check fails loudly, resume continues from the last acknowledged chunk. *(Task 5: `test_corrupt_payload_fails_integrity`, `test_duplicate_chunk_ignored`, `test_missing_chunk_never_completes`, `test_resume_from_last_acked`)*
5. Sync edge cases — duplicate client ids, `seq` gaps, a read receipt without delivery — no message is duplicated or lost; receipts never regress. *(Task 6: `test_duplicate_id_ignored`, `test_seq_gap_detected`, `test_read_implies_delivered`, `test_receipts_never_regress`)*
