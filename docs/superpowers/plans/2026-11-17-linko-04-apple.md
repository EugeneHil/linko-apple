# Linko Apple Implementation Plan (Plan 4 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `linko-apple` workspace — the iOS and macOS apps: Tuist project wired to the C++17 core, signaling and API clients on the server's wire contract, messaging with local storage and offline send, calls driven by the core state machine through WebRTC with CallKit, file transfer in-call (P2P) and via the server, the design system, and the v0.1 end-to-end acceptance run.

**Architecture:** One Tuist workspace, every module a framework with its own test target, built for iOS and macOS unless noted (spec §4.3). The `linko-core` submodule is built by a CMake script into a static library that only `CoreBridge` (Objective-C++, the single Swift↔C++ seam) links; everything above is Swift. DI via protocols and initializer injection, a composition root per app. Callback/delegate Apple APIs (WebRTC, CallKit, `URLSessionWebSocketTask`, `NWPathMonitor`, `AVAudioSession`) are wrapped once at the boundary into `AsyncStream`s (spec §7); where an API demands a synchronous answer (CallKit actions), the boundary adapter does exactly that and nothing more.

**Tech Stack:** Swift 6 language mode (strict concurrency `complete`), SwiftUI, Tuist 4.212.0 via mise, Xcode 27, `stasel/WebRTC` 155.0.0 (SPM binary, exact pin), GRDB (pinned), `URLSession`/`URLSessionWebSocketTask`, CallKit, `AVAudioSession`, XCTest; `linko-core` C++17 via submodule + CMake; SwiftLint `--strict` + SwiftFormat `--lint`.

**Spec:** `docs/superpowers/specs/2026-10-25-linko-design.md` (§2 goals, §3 constraints, §4.3 modules, §4.4 WebRTC, §4.5 endpoints, §4.6 TURN, §4.7 UI, §4.8 design system, §7 quality gates, §10 acceptance).

**Plan series:** 1 Foundation (done) → 2 linko-core (done) → 3 linko-server (done) → **4 linko-apple (this)**.

**Tickets:** this plan document is LNK-26; Tasks 1–15 are LNK-27…LNK-41.

## Global Constraints

- Platforms iOS 18+ / macOS 15+ (spec §3). Swift 6 language mode, strict concurrency `complete`, warnings are errors; Swift Concurrency only — no GCD, `OperationQueue`, Combine or completion handlers in our code (spec §7). SwiftLint `--strict` and SwiftFormat `--lint` gate every PR.
- Tuist 4.212.0 pinned via mise (`.mise.toml`), Xcode 27 (ADR-0001 spike-proven). No new dependency without an ADR; versions pinned exactly. New here: `stasel/WebRTC` 155.0.0 (SPM binary, exact pin + binary-artifact checksum recorded — closes ADR-0001's "not recorded"), GRDB, Tuist → ADR-0004.
- `linko-core` as submodule `external/linko-core` pinned to tag `v0.1.0` (same pattern as linko-server, ADR-0002/0003 dependency set comes with it).
- Wire contract (spec §4.2, §4.5 + linko-server README "Wire contract notes"): JSON envelopes ≤ 64 KiB (SDP ≤ 32 KiB), lowercase hex digests everywhere; SPKI pin = `base64(SHA-256(SPKI DER))`; endpoints `POST /api/v1/register`, `GET /ws` (`Authorization: Bearer`), `GET /api/v1/turn`, `PUT /api/v1/files` / `GET /api/v1/files/{id}`, `POST /api/v1/calls/{callId}/report`, `GET /api/v1/users?prefix=`; register replies `201 {"user","device","token"}`; TURN reply `{"username","credential","ttlSec","urls"}` (REST scheme, spec §4.6); invite link `linko://join?host=…&port=…&pin=…&code=…`.
- TDD: the failing test is written and watched first (CLAUDE.md). Coverage gate: ≥ 80 % lines of Swift logic — view models, coordinators, repositories, adaptation policy, stats derivation (spec §7).
- Secrets (spec §6): the device token lives only in the Keychain (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, not synchronizable); the SPKI pin must come from the invite link — no trust-on-first-use; never log tokens, invite codes, `Authorization`, message bodies, SDP or ICE credentials; no certificate/key files committed (the guard hook blocks `*.cer`/`*.pem` — test KATs embed public DER bytes as source constants, never keys).
- Free Personal Team signing only (spec §3): no PushKit/APNs; incoming calls reach the iPhone only while the app holds its WebSocket — the `IncomingCallSource` abstraction (spec §2) keeps PushKit pluggable; `voip` background mode next to `audio` is declared (spike-proven, ADR-0001); profiles expire after 7 days and are refreshed by rebuilding.
- Scope cuts applied (spec §1 order + repo reality): adaptation beyond the cellular/Low-Data-Mode bitrate cap (cut #3, spec); Mac ↔ Mac calls as a tested scenario (cut #4, spec); app-side device management (no client-facing devices endpoint exists in linko-server v0.1 — management stays CLI); H.264 hardware path and QR scanning are cut candidates below.
- Branches `feature/LNK-<n>-<slug>` → PR to `develop`; Conventional Commits; never commit to `main`/`develop`; repository text in English; anything on the VPS or the owner's iPhone happens only with the owner (Plan 1 Global Constraints).

## Review Focus

1. Hostile invite links and registration responses — malformed `linko://join` (missing pin, missing code, bad port, junk host), unexpected register bodies (malformed 201 JSON, wrong types) — rejected with typed errors before any network call or without crashing; username validated client-side exactly like the server. *(Task 5: `test_invite_link_without_pin_rejected`, `test_invite_link_missing_code_rejected`, `test_register_unexpected_response_is_error`)*
2. Hostile server envelopes on the wire — oversized frames (> 64 KiB), malformed JSON, unknown `type`, `v` mismatch — surfaced as errors or reconnects, never a crash, never reaching view models or the call coordinator raw. *(Task 2: `test_envelope_errors_carry_paths`; Task 4: `test_malformed_envelope_surfaces_error`, `test_oversized_frame_surfaces_error`, `test_unsupported_version_surfaces_error`)*
3. Duplicates, late messages and crossed calls on the client — duplicate `msg.deliver` ids, a second accept, glare (the lexicographically smaller `callId` survives), events for another call — no message duplicated or lost, exactly one call survives. *(Task 6: `test_duplicate_deliver_ignored`, `test_append_is_idempotent_by_id`; Task 9: `test_crossed_calls_smaller_id_survives`, `test_events_for_other_call_ignored`)*
4. Corrupt, duplicated or gapped file chunks and downloads — bit-flipped chunk, missing chunk, digest mismatch on a server download — integrity fails loudly, resume continues from the last acknowledged chunk, nothing silently accepted. *(Task 11: `test_corrupt_chunk_fails_sha256_loudly`, `test_missing_chunk_never_completes`, `test_download_verifies_digest`)*
5. Secret and pin hygiene under failure — a pin mismatch fails closed (no fallback, no TOFU), the device token never lands in `UserDefaults` or logs, `Authorization` never logged, SDP/ICE credentials never logged. *(Task 4: `test_pin_mismatch_fails_closed`; Task 5: `test_token_never_written_to_defaults`, `test_http_client_never_logs_authorization`)*
